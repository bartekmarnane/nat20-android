# iOS → Android UI Parity Audit & Roadmap

Audited 2026-07-02. Every view compared between `nat20-ios` and `nat20-android`.
Goal: Android matches iOS design as identically as possible.

## Verdict in one paragraph

The theming *primitives* are already an exact port (palette hex-for-hex, all four
typefaces, parchment background, diamond/divider ornaments — `ui/theme/`), and a
handful of screens use them faithfully (Settings, Onboarding, Roster,
Spell/Item reference shells, ReferenceTabShell chrome). But most Android screens
bypass that system and render stock Material3 (`Scaffold`, `TopAppBar`, `Card`,
`AlertDialog`, `FilterChip`, `MaterialTheme` typography). Beyond styling, the two
apps diverge on a core architectural axis: **iOS keeps the codex display-only and
routes every mutation through the Act pill → full-screen parchment pickers;
Android embeds interactions inline in the tabs and uses small Material dialogs.**
Closing the gap means (1) porting the shared chrome atoms, (2) re-theming the
off-pattern screens, (3) adopting the Act-pill/picker architecture, and
(4) filling missing screens/steps (campaign setup, wizard steps, item editing,
custom creatures, PDF export, etc.).

## Bugs found along the way (fix immediately)

- [ ] **Speed hardcoded to "30 ft"** on 2014 Combat tab — should use
      `payload.effectiveSpeed` (`ui/codex/CodexPages.kt:392`).
- [ ] **Roster campaign line hardcoded** to "No campaign yet" — real campaign
      name never wired in (`ui/roster/RosterScreen.kt:231`).
- [ ] **Credits screen is a licensing-compliance gap**: iOS lists 6 game-content
      attributions (SRD 5.1/5.2, 5e-bits, Open5e, PF Monster Core ORC, Archives of
      Nethys) with verbatim CC-BY/ORC text + links, and typeface designers + OFL
      link. Android collapses to 3 link-less cards. These attributions are
      license-mandated — treat as a bug, not polish (`ui/settings/CreditsScreen.kt`).

## Decisions (settled 2026-07-02)

1. **Interaction model: adopt the iOS Act-pill model.** Codex tabs become
   display-only; all mutations route through Act pill → parchment pickers.
   Android's inline buttons, dialogs, and tap-to-roll rows are removed as each
   surface reaches parity (P3/P4/P6/P7). Taps on medallions/saves open
   contribution popovers as on iOS.
2. **Android-only extras: strict parity — remove them**, with one exception:
   - **2024 level-up multiclass + HP roll is KEPT on Android and backported to
     iOS** (see "iOS follow-ups" below). The two apps converge on the richer flow.
   - Remove: persisted initiative (P6), PF2e in-play equipment/rune editing
     (P7, once the wizard Equipment step exists), "FUMBLE"/every-d20 flourish
     (P4), Replay-introduction tile (P2), per-denomination coin adjust where
     iOS uses the gold amount sheet (P4/P6).
   - Roster swipe-to-delete: remove **only when P8's per-character settings
     screen lands** — until then it is the only delete path on Android.
3. **AI describe cards: build the gated UI now.** Port the iOS describe /
   "Surprise me" concept cards into the New Character flow and each wizard's
   Name step, hidden behind the AI-availability flag (inert on current
   hardware; A20 wires the brains).
4. **PDF export: in scope** — P8 includes `android.graphics.pdf` exporters for
   all three rulesets + share flow.
5. **Patron:** screen re-theme lands in P2; purchase wiring stays stubbed until
   A14 (Play Billing).

## iOS follow-ups generated by this audit

      into `LevelUpSheet2024.swift` (decision #2) so both platforms match.

# Roadmap

Phases ordered so shared infrastructure lands first; each later phase is mostly
mechanical once its atoms exist. Sizes: S < 1 session, M ≈ 1 session,
L ≈ 2–3 sessions, XL ≈ 4+.

## P0 — Bug fixes & trivial parity (S) — DONE 2026-07-02

- [x] Effective speed on Combat tab — added `DnD5ePayload.effectiveSpeed`
      (catalogue race speed, 30 fallback); Combat tab uses it.
- [x] Real campaign name on roster cards — new `CampaignDao.observeActiveCampaignNames`
      → `CharacterStore.activeCampaignNames` StateFlow → roster card shows diamond +

      entries (SRD 5.1/5.2, 5e-bits, Open5e, PF Monster Core ORC, AoN) with

## Suggested order & why

P0 (bugs) → P1 (atoms unlock everything) → P3 (2014 codex is the daily-driver
surface) → P4 (actions are the core play loop) → P2 (broad but mechanical
re-theme) → P5 (wizard) → P6 (2024) → P7 (PF2e) → P8 (feature gaps) → P9 (QA).
Campaign setup + journal (P8 first two items) are worth pulling forward if
campaigns are the next thing you'll demo — they're the most visible gaps in a
live session.
